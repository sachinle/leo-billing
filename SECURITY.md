# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | ✅                 |
| < 1.0   | ❌                 |

## Reporting a Vulnerability

If you discover a security vulnerability in **Leo Billing**, please **do not open a public GitHub issue**.

Instead, report it privately:

- **Email:** sachinimmanuel2006@gmail.com
- **Subject:** `[SECURITY] Brief description of the issue`

### What to include

- Description of the vulnerability
- Steps to reproduce it
- Potential impact
- Any suggested fix (optional)

### What to expect

| Timeline | Action |
| -------- | ------ |
| Within 48 hours | Acknowledgement of your report |
| Within 7 days | Initial assessment and response |
| Within 30 days | Fix released (if accepted) |

If the vulnerability is **accepted**, you'll be credited in the release notes (unless you prefer to stay anonymous).

If the vulnerability is **declined**, we'll explain why with as much detail as possible.

---

> This project uses Firebase Auth, Supabase (PostgreSQL), and Capacitor.
> Please treat any issues involving user data, authentication bypass, or
> invoice data exposure as **high severity**.
